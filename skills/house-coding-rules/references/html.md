# HTML
Baseline: [WHATWG HTML](https://html.spec.whatwg.org/), [WCAG 2.2](https://www.w3.org/TR/WCAG22/).
- Use semantic landmarks, a logical heading order, native buttons/links and associated form labels. Use ARIA only where native semantics cannot express the interaction.
- Provide keyboard access, visible focus, descriptive errors and deliberate dialog focus/return behaviour. Announce asynchronous status without unnecessary focus jumps.
- Encode untrusted text/attributes; validate link destinations. Avoid inline script handlers and establish an appropriate CSP.
- Test accessible names, keyboard flows, invalid forms, history/cancellation and responsive layouts in a browser. Static validation alone does not establish accessibility.
- Use the project's HTML validator/accessibility checks where configured; record manual and automated coverage separately.
